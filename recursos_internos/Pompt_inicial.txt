Prompt inicial — landing page Creciendo Juntos

Construir un landing page en español llamado Creciendo Juntos.

Objetivo del landing
Convencer al visitante y llevarlo a contactar por WhatsApp. Esa es la llamada a la acción principal de la página.

Qué es el negocio
Los dueños son psicólogos. Creciendo Juntos se relaciona con estimulación temprana, con el desarrollo de los niños y con un crecimiento psicológico sano. El landing debe transmitir eso: cuidado, familia, infancia y rigor profesional de psicología. No es una tienda genérica ni un sitio clínico frío.

Servicios
Fuente: `recursos_internos/Servicios.jpeg`. Usar esta lista en la sección Servicios. No añadir, fusionar ni inventar otros servicios. No inventar descripciones largas si no están en el flyer.

- Evaluación del desarrollo (0 a 5 años)
- Estimulación e intervención temprana (6-36 meses)
- Terapia de atención, concentración y conductual en niños
- Manejo de ansiedad, estrés y depresión
- Intervención en problemas conductuales y emocionales en adolescentes
- Orientación y consejería familiar
- Escuela para padres
- Talleres de desarrollo personal y conductas saludables

Dirección de diseño
Estética moderna. Cálida y profesional a la vez.

Debe sentirse:
- Estimulación temprana y crecimiento: movimiento suave, espacio para respirar, sensación de acompañar a la familia.
- Psicología: confianza, calma, seriedad; no infantilizar el oficio.
- Moderno: layout limpio, tipografía contemporánea, jerarquía clara, buen ritmo, recortes actuales. No plantilla de 2010, no “web de niños” recargada.

Evitar:
- Clipart, emojis como identidad, arcoíris de juguete, globos, comic sans o equivalentes.
- Estética de hospital, clínica genérica o corporativo frío.
- Inventar una paleta o tipografía distinta a la del logo. Tomar cues de color del logotipo (violeta, naranja, verde del niño) sin convertirlos en un sistema inventado ni en un look infantil saturado.

El visitante debe entender al primer vistazo que aquí hay psicólogos que acompañan el crecimiento de niños, no un entretenimiento suelto ni un consultorio anónimo.

Arquitectura
Stack: monorepo (pnpm workspaces + Turborepo) + TypeScript. El sitio público es Next.js (App Router) en `apps/web`. Hay backend previsto (login de administrador e integración SUNAT), por eso el repo nace como monorepo y no como app suelta que luego hay que partir.

Por qué monorepo desde el inicio
El landing es la primera entrega, pero «Iniciar sesión» y SUNAT van a necesitar API, secretos y lógica de servidor. Un solo Next.js con todo mezclado se vuelve frágil. Separar `apps/web` y `apps/api` desde la estructura (aunque el API aún no se implemente) deja el proyecto listo sin reescribir el landing.

Estructura
```text
/
  apps/
    web/                 # Next.js App Router — landing y, más adelante, UI de admin
    api/                 # futuro backend (auth admin, comprobantes, SUNAT). No implementar ahora
  packages/
    typescript-config/   # tsconfig compartido
    eslint-config/       # lint compartido
  recursos_internos/     # brief, logo y fotos fuente. No es código de producción
  pnpm-workspace.yaml
  turbo.json
  .env.example
```

`apps/web` (App Router)
```text
apps/web/
  src/app/
    layout.tsx           # lang="es", metadata, header/footer
    page.tsx             # landing de una sola página (secciones con anclas)
    iniciar-sesion/
      page.tsx           # placeholder; sin auth real en esta entrega
    globals.css
  src/components/        # Header, HeroCarousel, Servicios, Footer, etc.
  public/                # logo y fotos del carrusel (copias de recursos_internos)
```

Reglas de la arquitectura
- TypeScript estricto. Server Components por defecto; `"use client"` solo donde haga falta (carrusel, menú móvil).
- Estilos: Tailwind CSS + tokens/cues de color del logotipo. No otro framework de UI ni plantilla marketplace.
- Alias `@/` hacia `src/`.
- `recursos_internos/` es fuente de diseño; los assets que sirve la web se copian a `apps/web/public/` (nombres estables).
- El landing es estático en la práctica: sin CMS, sin base de datos y sin llamadas a SUNAT en esta entrega.
- `Iniciar sesión` apunta a `/iniciar-sesion` en `apps/web`. Auth, sesión y SUNAT viven en `apps/api` cuando existan. Nunca credenciales ni API de SUNAT en el cliente.
- Secretos solo en `.env.local` (no commitear). Documentar claves vacías en `.env.example`.
- ESLint + Prettier. `pnpm dev` / `pnpm build` / `pnpm lint` desde la raíz via Turbo.
- SEO básico: `metadata` en el layout (título Creciendo Juntos; no inventar descripción de marketing si no está definida).
- Hosting: pendiente. Encaja Vercel para `apps/web`; el API se decide cuando se construya.
- No implementar `apps/api` ni el flujo SUNAT en el primer corte del landing. Dejar la carpeta o el workspace listo, vacío o con un README de intención.

Para qué existe Iniciar sesión
Da entrada a un área privada donde el administrador se conecta a la API de la SUNAT (Superintendencia Nacional de Aduanas y de Administración Tributaria, Perú). Desde ahí se envían los comprobantes/recibos de los servicios que brinda el negocio y se cubre lo necesario ante SUNAT.

En este landing:
- Mostrar el botón Iniciar sesión en el top bar.
- No implementar todavía el login, el área privada ni la integración con SUNAT.
- El botón puede apuntar a una ruta futura (por ejemplo /admin o /iniciar-sesion) o quedar como control visible sin flujo completo.
- No pedir registro al público. No sugerir que los clientes tengan cuenta.
